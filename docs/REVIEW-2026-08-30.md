# Full-codebase review — 2026-08-30

Five parallel area reviews (pipeline core, toolbelt, server/infra, deterministic
outputs, web JS) plus an ops-layer pass. Every item below was verified against
the code at commit 4a85c71 with file:line evidence; overlapping discoveries are
merged. Nothing here is fixed yet — this is the inventory the fix plan works from.

## A. Availability & money (production ops)

- A1 **Zombie-run lockout.** Crashed workers/instances never mark run docs
  terminal; `count_running` (runstate.py:136) has no staleness filter and
  saturates at limit(25). Five zombies = permanent fleet-wide 429 until manual
  Firestore surgery. Worker has no SIGTERM handler; server's SIGTERM handler
  (server.py:108) is dead under uvicorn (uvicorn replaces it) and never wrote
  clearance-run terminal status anyway.
- A2 **Kill switch + invites silently expire after 7 days.** The pause flag and
  invite redemptions are stored via `load_research`, which TTLs everything at 7
  days (storage.py:134). A paused site un-pauses itself; redeemed invites lapse
  weekly. (Switch is ON since 2026-08-29 → would lapse ~09-05.)
- A3 **Unauthenticated LLM spend.** `/api/fix` (server.py:1675) and
  `/api/whatif` take no sign-in against the public demo run id; rate keys use
  the FIRST X-Forwarded-For entry, client-controlled on Cloud Run → unbounded
  Gemini spend via header rotation. All four limiter dicts are per-instance
  (multiply under scale-out, reset at scale-to-zero); `_client_log_rate` never
  prunes (unbounded memory).
- A4 **Done-before-save (in-process).** `_run_live` writes status=done/
  record_saved BEFORE `storage.save_record` (server.py:645-656); a crash in the
  window loses a paid run with a positive status. Worker orders correctly.
- A5 **Worker retry corrupts the journal.** `JournalPublisher._seq` restarts at
  0 per attempt; Cloud Run Job retries interleave two attempts' chunks
  (runstate.set overwrites same-seq, orphans differing boundaries).
- A6 **Racy admission.** `_check_rate`/cap check is read-then-act with no
  reservation; N concurrent uploads all pass at running=4.
- A7 `save_record` double-call is not a retry (no backoff; both fail together)
  (worker.py:147). `_bump` durable increments are fire-and-forget and droppable.
- A8 `previous_run_id` ownership check fails OPEN when `load_owner` errors
  (server.py:749; storage.py:233).
- A9 Session cookies: no revocation; logout cosmetic; ADMIN_EMAILS removal
  ineffective until 30-day expiry. `/api/admin/pause` returns 403 while the
  rest of admin 404s (existence leak, inconsistency).
- A10 `_journal_relay` never terminates for zombie runs (one live SSE poll loop
  per viewer, forever) (server.py:1879).
- A11 Latent traversal: `record["script_path"]` trusted as filesystem path in
  `_load_source_any` (server.py:1379) with no containment check (currently
  unreachable externally). `_safe_id` applied inconsistently across readers.
- A12 PII: owner email/name embedded in run stubs (server.py:543) — within the
  owner's prefix, but privacy-page accounting should note it.

## B. Report integrity (verification, agents, accounting)

- B1 **Fail-open verifier inflates the score to 100/100.** `_scored()` excludes
  `verification_unavailable` flags from score/cost/dimensions while counts keep
  them (report.py:28,94). Verifier-down run → 100/100 beside "3 blockers".
  Print surfaces render fail-open flags with NO marker (binder/one-sheet), and
  wholesale salvage-verify failure keeps every flag unmarked (pipeline.py:286).
- B2 **`{target_rating}` never reaches the Ratings Board.** Callable
  instruction providers bypass ADK state injection; only 4 placeholders are
  substituted (common.py:280-330). The desk guesses the target; cut lists are
  built against an assumed target. Same in the retry copy.
- B3 **Ratings retry cannot file a prediction.** `query_precedent`/
  `rating_boundary` write agent-keyed (`last_precedent:{agent}`,
  toolbelt.py:1760,2086); `file_rating_prediction` reads desk-keyed
  (toolbelt.py:1829,1838,1882). `ratings_board__retry` burns 6 iterations on
  "no comparables". Related: a desk that filed a prediction but no per-item
  dispositions counts as "collapsed" and is forced into that broken retry.
- B4 **Sweeper work is invisible for non-clearance desks.** Sweep writes land
  under `clearance_counsel__sweep`; `unexamined_entities` per-desk families
  never include it for ratings/safety/territory → items re-swept every round,
  then rendered NOT EXAMINED despite being examined (toolbelt.py:99-147,
  completeness.py:116-131 also drops work_item_id from sweep items). Entity
  items dispositioned by work_item_id only are likewise invisible (B4b).
  `collapsed_desks` counts sweeper flags as the desk's own (masks collapse).
- B5 **Recovered flags keep their UNSUPPORTED base verdict** (`verdicts:{fid}`
  never updated; only `:resourced` written — verification.py:939) and carry
  stale `failure_mode` metadata; the summary line double-counts `:resourced`.
- B6 **Code-dedupe runs before `apply_plan` and can void the plan** (absorbed
  survivor id → merge/normalization/rationale silently no-op) (pipeline.py:444).
- B7 **flag_id collision past seq 99**: per-desk sequence increments on every
  attempt incl. rejections; clearance F201 collides with ratings F201
  (toolbelt.py:33,1491).
- B8 **Script-quote provenance leg is dead**: checks `state["source"]`, which
  nothing writes (toolbelt.py:1189); legitimate script-verbatim citations
  always fail, and ≥60% auto-repair can REPLACE a script quote with unrelated
  research text. Auto-repair also files normalized/truncated text as
  "verbatim" (lowercased, [:800] mid-word slice).
- B9 **Host/authority classification holes**: case-sensitive host matching;
  scheme-less URLs classify background+non-authority; `"gov" anywhere in
  labels` passes (gov.fandom.com); two-label `_host_root` breaks bbfc.co.uk
  subdomains; url-less citations (rules_table, precedent) always "background"
  so recommended local evidence can't carry MEDIUM+; category gate keys on
  literal "rating_"/"territory_" prefixes of free-text categories.
- B10 **Coverage credit by unanchored substring**: `"ford" in "…cannot
  afford…"` credits entity "Ford" (toolbelt.py:122,2380) — short-surface
  entities can be skipped and never disclosed.
- B11 Budget races/accounting: `fetch_page`/`deep_research` unlocked RMW with
  refund-by-stale-snapshot (double-spend); `desk_budget_left` ignores base key
  once any suffixed key exists (done() lazily creates one → run summary lies);
  per-batch ceil over-allocates; `_DEEP_MAX_PER_DESK` is per-instance (up to
  12 deep runs for clearance family). Re-source searches escape `cost_usd`
  and session grouping (`parallel_session_id` has no writer;
  `resource_searches` has no reader).
- B12 Gate ceremony waste: retry/sweep LoopAgents can never escalate → up to
  ~90 idle Flash calls/run; re-source loop is fully sequential (adds minutes).
- B13 Salvage-path divergence: no re-source, no demotion-to-OQ, no rating
  reconcile, no verdicts/state writes (overturns DO run — parity there).
- B14 Post-run crash risk: `state.get("triage", {}).get(...)` unguarded at
  pipeline.py:499 while four sibling call sites defend the pydantic form.
- B15 `AdjudicationPlan.notes` demanded from Pro, then discarded.
- B16 Misc: research errors all render "budget spent"; triage entity count ~2x
  (counts worklist ids); `apply_verdicts` docstring still claims the removed
  PARTIAL cap; dead keys (`SEVERITY_ORDER`, `done_refusals` reads,
  `prepass_added`); `_hard_person` fields never joined onto worklist items
  (prioritization inert); territory prompt overpromises done() (budget<3
  closes with axes open); `_unverified_regs` misses "Registration No." and
  other-desk verifications; `find_in_script` unbounded output + uncompiled
  model-supplied regex on the event loop; `queries` not coerced when passed as
  a bare string (live 400s count toward the breaker); research dedupe waiter
  can wake a third caller early (documented-behavior check).
- B17 Direct `ctx.session.state` mutation in completeness/verification
  (unjournaled; lost under a persistent session service).
